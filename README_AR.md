# OGEIDA CRM — حزمة بدء مشروع جديد

## محتويات الحزمة
- `app/index.html`: واجهة الموظفين (آخر نسخة معدلة متاحة).
- `app/admin/index.html`: لوحة الأدمن (آخر نسخة معدلة متاحة).
- `app/config.js`: قالب إعدادات Supabase فارغ للمشروع الجديد.
- `supabase/schema.sql`: مخطط قاعدة البيانات الأساسي.
- `supabase/migrations/001...005.sql`: ملفات تعديلات الصلاحيات والفريق وFeedback والتسجيلات الصوتية.
- `TEST_STATUS_AR.md`: حدود الفحص الحالي وما يلزم اختباره.

## خطوات الربط
1. أنشئ مشروع Supabase جديدًا منفصلًا عن القديم.
2. هذه الحزمة لا تنقل بيانات المشروع القديم.
3. راجع `schema.sql` وكل ملفات migrations قبل التنفيذ. اختبر في مشروع Development جديد أولًا.
4. لا تنفّذ SQL قبل التأكد من توافق المخطط الأساسي مع جميع migrations وعدم وجود نسخ مطبقة مسبقًا. الترتيب المقترح: schema.sql ثم migrations من 001 إلى 005.
5. ضع Project URL و anon/public key للمشروع الجديد داخل `app/config.js`.
6. ارفع محتويات `app` إلى الاستضافة مع الحفاظ على المسارات: `index.html` و`admin/index.html` و`config.js`.
7. اختبر بحسابات Admin وSales وTeam Leader قبل الإطلاق.

## تنبيهات أمنية
- لا تضع `service_role` key في `config.js` أو أي ملف Frontend.
- لا تستخدم إعدادات Supabase الخاصة بالمشروع القديم.
- لا تشغّل SQL على Production قبل مراجعة السياسات وأخذ Backup.
- وجود ملفات SQL في الحزمة لا يعني أنها اختُبرت أو طُبقت على مشروعك الجديد.
